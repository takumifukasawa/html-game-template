# three.js のシェーダーと描画の落とし穴

テンプレートから作るどのゲームでも起こりうる、シェーダーと描画まわりの落とし穴。bloom のチカチカは [three-bloom-flicker.md](three-bloom-flicker.md)。

## 共通の uniform と名前が被ると、上書きされる

- 症状: マテリアルの uniform の値を設定しても効かない。関係ないタイミングで値が変わる。
- 原因: `uniforms: {...自分の uniforms, ...共通の uniforms}` のように混ぜると、後ろに書いた共通側の同じ名前が勝つ。自分の値のつもりで書き換えると、共通の値（ほかの全マテリアルが見ている値）を書き換えてしまう。
- 対策: 共通の uniform 名は一覧にして決めておき、各マテリアルでは別の名前を使う。おかしいと思ったら、まず uniform 名の重複を検索する。

## カメラの周りで折り返す要素は、すべての軸の継ぎ目を消す

- 症状: 背景の要素（粒・線など）が、カメラが動いたときにパッと消えたり出たりする。
- 原因: 要素を `fract` などでカメラの周りに折り返して使い回すと、範囲の端が継ぎ目になる。奥にある要素ほど、画面に見える範囲が広い。そのため、範囲が狭いと継ぎ目が画面に入る。横は消していても、縦を消し忘れていることが多い。
- 対策: 折り返すすべての軸で、継ぎ目の近くを薄く消す（例: `smoothstep(half, half * 0.72, abs(offset))`）。範囲は、いちばん奥の要素が見える範囲より広くとる。

## `pow(x, y)` の x が負のときの結果は未定義

- 症状: ある環境でだけ、画面の一部やすべてが真っ黒になる。
- 原因: GLSL の `pow` は、x < 0 のときの結果が決まっていない。実装によって NaN（黒）になる。ソフトウェア描画では出ず、実機の GPU でだけ出ることがある。`sin` などは、ぴったり 0 のはずの位置でもわずかに負になる。
- 対策: `pow(max(x, 0.0), y)` にする。

## 細すぎる点や線は、動くとちらつく

- 症状: 小さな点や細い線が、動くたびにちらちらする。
- 原因: 1 ピクセル前後の大きさだと、ピクセルの境目をまたぐたびに明るさが変わる。
- 対策: 最小の大きさを決め（例: 点 2px、線 1.5px）、それより小さい分は大きさを保って、面積の比で暗くする。
