# three.js の描画を、低スペックのスマホ向けに軽くする

テンプレートから作るどのゲームでも効く、描画の負荷の落とし穴。描画が重いと、絵がかくつくだけでなく、Android では音の処理まで遅れて、音がぶつぶつすることがある（音の側の原因と調べ方は [webaudio-android-crackle.md](webaudio-android-crackle.md)）。

## 後処理（EffectComposer）を使うなら、キャンバスの antialias は切る

- 症状: 見た目は変わらないのに、GPU の負荷とメモリだけが余計にかかる。
- 原因: `new THREE.WebGLRenderer({antialias: true})` は、キャンバス（画面のバッファ）に MSAA（輪郭をなめらかにする処理）をかける。EffectComposer で bloom などの後処理をしていると、シーンは後処理のバッファ（`WebGLRenderTarget`）に描く。キャンバスには、最後に画面いっぱいの四角を 1 枚描くだけになる。キャンバスの MSAA は、輪郭のない四角に毎フレーム効いていて、空回りしている。
- 対策: 後処理を使うときは `antialias: false` にする。輪郭のなめらかさは、後処理のバッファの `samples`（MSAA）で決まる。後処理を切ってキャンバスに直接描くときだけ、`antialias: true` にする。テンプレートの `ThreeApp` は `antialias` を指定しないと `true` なので、後処理を使うゲームでは `false` を渡す。

## 重くなりやすい設定と、実機で比べるためのスイッチ

次の設定は、URL のクエリで切り替えられるようにしておく（例: `?msaa=0&ratio=1&bloomscale=0.5`）。そうすれば、作り直さずに実機で比べられる。

| 設定 | 重さの理由 | 下げたときの見た目 |
|---|---|---|
| 解像度の倍率（`setPixelRatio`） | 描くピクセル数は倍率の 2 乗で増える。高解像度の端末（倍率 2.75 など）で、そのまま使うと重い | 1.5 くらいで頭打ちにしても、ほとんど分からない。1 にすると少しぼやける |
| 後処理のバッファの MSAA（`samples`） | half float のバッファに 2〜4 倍の MSAA をかけると、メモリの読み書きが多い | 細い線の輪郭が少しギザつく |
| bloom のバッファの解像度 | bloom の明るい部分を取り出す処理と、ぼかしの処理が、解像度に比例して重い | 半分にすると、細い光がちらつきやすくなる（[three-bloom-flicker.md](three-bloom-flicker.md)） |
| `preserveDrawingBuffer: true` | 毎フレーム、画面のバッファを捨てずに残すので、モバイルの GPU では重い | 指定しない（既定の false）。スクリーンショットが必要なときだけ、描いた直後に読む |

- 効いたかは、見た目の印象ではなく測る。たとえば同じ操作を自動で再現して、フレーム時間や、音の途切れの回数（上のリンク先の記録）を比べる。端末は続けて試すと熱で遅くなるので、間を空けて比べる。
